# 2026-08-13: Obj Loader and Mesh Viewer nodes for MathNodeEditor

## Goal

Add two node types to `MathNodeEditor`: an Obj Loader that splits a
triangulated `.obj` into Vertex/Face/UV/Normal graph outputs, and a Mesh
Viewer that merges those (after optional matrix transforms) back into a
mesh and renders it live using PyNGL's built-in shaders, with Solid
Colour/Diffuse shading and a wireframe option.

Full design rationale in
`docs/superpowers/specs/2026-08-13-mathnodeeditor-obj-mesh-nodes-design.md`.

## Files changed

- `MathNodeEditor/math_graph.py` — `VertexArray`/`NormalArray`/`UVArray`/`FaceArray`
  value types, `LiteralNode`/`MeshViewerNode` graph nodes, `MAT4_TO_MAT3`/
  `INVERSE`/`TRANSFORM_VERTICES`/`TRANSFORM_NORMALS` operations,
  `arrays_from_obj`/`obj_from_arrays` conversion helpers, `evaluate_mesh_viewer`.
- `MathNodeEditor/graphics_items.py` — multi-output port support
  (`PortItem.source_node_id`, `BaseNodeItem.owned_node_ids()`),
  `ObjLoaderNodeItem`, `MeshViewerNodeItem`.
- `MathNodeEditor/mesh_view.py` (new) — shared render/merge logic for the
  embedded `QOpenGLWidget` preview and the pop-out `QOpenGLWindow`.
- `MathNodeEditor/canvas.py` — node factories, connection/deletion/save-load
  updates for multi-output nodes, mesh viewer evaluation in `update_outputs`.
- `MathNodeEditor/palette.py`, `MathNodeEditor/node_editor.py` — catalogue
  entries, `QSurfaceFormat` + `Qt::AA_ShareOpenGLContexts` setup in `main()`
  (previously unset since the editor had no OpenGL surfaces before this).
- `MathNodeEditor/tests/` — new headless coverage plus two fixture `.obj`
  files; two existing tests updated for the new "Mesh" catalogue group.
- `MathNodeEditor/README.md`, `MathNodeEditor/MathNodeEditor.png`, root
  `README.md` — documentation and screenshot.

## Notable fixes found during manual verification

- Missing `QSurfaceFormat` setup meant the embedded `QOpenGLWidget` got a
  legacy GL 2.1 context and `glGenVertexArrays` failed outright.
- The pop-out `QOpenGLWindow` doesn't share a GL context with the embedded
  `QOpenGLWidget` by default, so `ShaderLib` program ids from one were
  invalid in the other (`glUseProgram` "invalid value"). Fixed with
  `QApplication.setAttribute(Qt.ApplicationAttribute.AA_ShareOpenGLContexts, True)`
  before the `QApplication` is constructed.
