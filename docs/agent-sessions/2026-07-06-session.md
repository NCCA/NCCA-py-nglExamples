# Agent session — 2026-07-06

## Goal

Create a new PyNGL demo (`SelectionManipulator/`) showing DCC-style object
selection and manipulation: colour-ID picking, a `SelectionObject` base class
whose selected instances render with solid diffuse shading plus a wireframe
overdraw, Maya-style Translate / Rotate / Scale gizmos with Q/W/E/R mode keys,
and ctrl+click multi-selection with group transforms.

## Files changed (all new)

- `SelectionManipulator/SelectionObject.py` — abstract base class (transform,
  display colour, unique colour ID, wireframe-overdraw selected rendering) and
  five concrete primitive subclasses.
- `SelectionManipulator/Manipulator.py` — gizmo drawing (arrows / rings /
  boxes built from stock primitives), reserved-ID handle picking, screen-space
  drag maths for translate, per-axis scale, and atan2-based rotate.
- `SelectionManipulator/main.py` — application window, scene, pick pass,
  Maya-style camera (alt+mouse) and Q/W/E/R mode keys, group transforms.
- `SelectionManipulator/README.md`, `SelectionManipulator/SelectionManipulator.png`.

## Commands run

- `git worktree add .worktrees/selection-manip -b agent/selection-manip`
- Automated smoke test (drives the real window: picks every object via the ID
  pass, verifies pivot centroid, all three gizmo axes pickable, simulated
  translate/rotate/scale drags, GL error check, screenshots) — 18/18 pass.
- `uvx ruff check` (clean) and `uvx ruff format`.

## Notes

- Found an upstream PyNGL bug: `Primitives.create(Prims.LINE_GRID, ...)` is
  broken — `_primitive` always builds a GL_TRIANGLES VAO with an 8-float
  vertex layout, but `PrimData.line_grid` emits 3-float line vertices. The
  demo builds its grid VAO manually with `VAOFactory` / `GL_LINES` instead.
- Session export: `opencode export` is not available in this harness
  (Claude Code); this summary document serves as the session record.

# Agent session — 2026-07-06 (continued): WebGPU port

## Goal

Port the `SelectionManipulator` OpenGL demo to the `ncca.ngl.webgpu` stack,
reusing the pre-existing `PipelineFactory` pipelines where possible.

## Files changed (all new, `SelectionManipulatorWebGPU/`)

- `main.py` — `WebGPUScene(WebGPUWidget)`: Maya controls, camera, multi-pass
  render, offscreen colour-ID picking with texture readback.
- `ObjectPipeline.py` — custom instanced diffuse pipeline; storage buffer of
  per-object model/normal/colour/pick-colour/selected; `render_mode` uniform
  toggles shaded vs flat pick output.
- `ObjectShader.wgsl` — diffuse + single-pass barycentric wireframe
  (`vertex_index % 3`, `fwidth` AA), flat pick mode.
- `SelectionObject.py` — same ABC + 5 subclasses, now emitting a storage-buffer
  instance dict instead of GL draw calls.
- `Manipulator.py` — gizmo geometry + drag maths unchanged; returns
  `(buffer, count, mvp, colour)` part-draw tuples instead of drawing.
- `WebGPUWidget.py` — local copy of the shared widget (from WebGPUMultiGeo).
- `README.md`, `SelectionManipulatorWebGPU.png`.

## Design decisions (asked the user)

- Wireframe overdraw → single-pass barycentric (no `glPolygonMode` in WebGPU).
- Reuse factory pipelines: grid = `SINGLE_COLOUR_LINES`, gizmo + gizmo picking =
  `SINGLE_COLOUR_TRIANGLES`; one custom pipeline only for the diffuse objects.

## GL → WebGPU mappings

- `glReadPixels` pick → offscreen MSAA→resolve texture, `copy_texture_to_buffer`,
  read 9×9 block.
- `glClear(GL_DEPTH_BUFFER_BIT)` gizmo overdraw → per-part pass that loads colour
  but clears depth on the first part.
